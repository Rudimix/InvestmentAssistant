# Investment Assistant

Telegram-бот — инвестиционный ассистент поверх брокера Т-Инвестиции. Бот общий, а данные у каждого
свои: пользователь подключает собственный токен T-Invest API командой `/connect` и видит только свои
счета, портфель и журнал.

* **личное подключение**: `/connect` — токен (сообщение с ним бот сразу удаляет, в базе токен хранится
  зашифрованным), `/accounts` и `/account N` — выбор счёта, `/disconnect` — удалить токен;
* **журнал гипотез**: `/idea` записывает решение buy/sell/hold с текущей ценой, `/review` проверяет,
  подтверждается ли гипотеза, `/close` фиксирует результат;
* **рыночные данные и портфель** через [официальный MCP-сервер Т-Инвестиций](https://developer.tbank.ru/invest/mcp):
  `/price`, `/stats` (SMA, волатильность, просадка, тренд), `/portfolio`. Работают акции, облигации,
  фонды и фьючерсы: тикер `SBER` сам переводится в `SBER_TQBR`, `SiZ6` — в `SiZ6_SPBFUT`;
* **свободный диалог** с любой LLM, у которой есть OpenAI-совместимый API (OpenAI, DeepSeek,
  OpenRouter, Ollama, LM Studio...). Модель сама вызывает MCP-инструменты, но только для чтения.
* **анализ выбранного портфеля**: `/analysis` — структура, концентрация, изменения между снимками,
  доступные новости, календарь отчётности и объяснение AI с привязкой к показателям и источникам.

Ассистент **не торгует**: LLM получает только список инструментов чтения (без заявок, стоп-заявок
и операций со счетами). Пользователям стоит выпускать токен «Только чтение» — тогда торговать
запретит сам сервер Т-Инвестиций; если у токена есть право на сделки, бот предупредит.

Безопасность токенов:

* токены шифруются ключом `TOKEN_ENCRYPTION_KEY` (Fernet); без ключа база с токенами бесполезна,
  а при смене ключа пользователям придётся подключиться заново;
* сессия MCP открывается на время одного запроса с токеном того, кто спросил;
* бот отвечает только в личных чатах; токен, присланный обычным сообщением, удаляется и не уходит к LLM.

Python 3.12 или новее.

## Архитектура

```
Telegram ──► bot.py (aiogram 3) ──► connections.py ──► storage.py (SQLite: журнал, зашифрованные токены)
                 │                       │ токен пользователя
                 └──► llm.py (агент) ──► journal.py, market.py ──► mcp_client.py ══HTTPS══► invest-public-api.tbank.ru/mcp
```

Сервер Т-Инвестиций использует сертификат Минцифры, которого нет в стандартном наборе Python.
Скачайте с https://www.gosuslugi.ru/crt корневой и выпускающий сертификаты и положите их в `certs/`
(пути задаются в `TINVEST_CA_FILES`). Они используются только для соединения бота с сервером
и в систему не устанавливаются.

## Установка

~~~sh
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
python -m pip install -e .
copy .env.example .env            # заполните TELEGRAM_BOT_TOKEN, при желании LLM_*
python -m investment_journal --generate-key   # ключ — в TOKEN_ENCRYPTION_KEY
~~~

Токен T-Invest API каждый пользователь подключает сам в боте (`/connect`). Для проверки без риска
запустите бота с песочницей (`TINVEST_SANDBOX=1`).

Проверить подключение со своим токеном (`TINKOFF_TOKEN` в `.env`, боту он не нужен) и посмотреть
инструменты сервера:

~~~sh
python -m investment_journal --list-tools
~~~

## Запуск

~~~sh
investment-assistant              # или: python -m investment_journal
~~~

## Аналитический отчёт

Выберите счёт через `/accounts` и `/account N`, затем отправьте `/analysis`. Бот получает актуальный
портфель, сохраняет снимок и отправляет отчёт с составом, долями, крупнейшими позициями и доступными
событиями. Длинный отчёт приходит несколькими пронумерованными сообщениями с исходными ссылками.

Первый анализ создаёт исходную точку. Следующие отчёты показывают фактический период сравнения,
появившиеся и закрытые позиции, денежные изменения, внешние пополнения и выводы, подтверждённые
вклады и нераспределённую часть. Ручные и автоматические отчёты имеют отдельные точки сравнения.
История разделена по пользователям и счетам. Для анализа произвольных дат используйте
`/analysis период` и укажите часовой пояс, начало и конец. Доступен прямой ввод
`/analysis 01.10.2026 31.10.2026 Europe/Moscow` и последние завершённые календарные дни
`/analysis 30 Europe/Moscow`. Отмена диалога — `/cancel`. Команда `/analysis` без аргументов
сохраняет описанное выше сравнение с предыдущим снимком.

Исторический анализ восстанавливает состав и деньги по операциям от текущей опоры, включая
проданные бумаги. Предварительный снимок для выбранного периода не требуется. Конечная местная
дата включается целиком, сегодняшний день ограничивается временем запроса. Границы сохраняются
перед сбором данных и сохраняются при повторе доставки после полуночи.

Для оценок используются завершённые часовые свечи до границы, не старше 14 суток, и исторические
курсы. Облигации оцениваются по процентной цене, номиналу и НКД соответствующей даты в московском
календаре брокера. У фьючерсов денежная оценка требует подтверждённых исторических параметров
шага и цены последнего маржинального расчёта. Известные корпоративные действия требуют
подтверждения базы корректировки свечей. При недостатке данных отчёт показывает оценённую часть,
неизвестные компоненты и покрытие. Полнота корпоративной истории MCP отдельно не гарантируется.
Денежный результат после внешних потоков доступен при подтверждённых итогах и денежных движениях.
Сохранённые входы позволяют повторить расчёт без обращения к текущим рыночным данным.

### Профиль потребностей

`/profile` последовательно запрашивает цель, горизонт в месяцах, категорию риска, допустимую
просадку, минимальный денежный остаток с валютой и максимальные доли позиции и сектора.
Проценты вводятся в диапазоне больше 0 и до 100 включительно, остаток — неотрицательной суммой,
например `10000 RUB`. После предпросмотра нажмите «Сохранить профиль». `/cancel` сохраняет
предыдущую подтверждённую версию.

Каждое подтверждение создаёт новую версию. Отчёт фиксирует её при постановке в очередь.
Изменение профиля перед отправкой отменяет устаревшее выполнение, повторный запрос использует
актуальную версию. Сохранённые части отчёта связаны с исходной версией.

Отчёт сравнивает доступные доли с ограничениями, показывает нехватку денежного остатка и
валютные и отраслевые экспозиции. Отсутствующие оценки, сектора и валютный пересчёт обозначаются
явно. При коротком горизонте указывается несовместимость с прогнозом на 12 месяцев.
Допустимая просадка является заявленным ограничением пользователя. Анализ портфеля доступен
и без профиля, персональные ограничения в этом случае заполняются через `/profile`.

### Предложения и журнал

После подтверждения профиля `/analysis` показывает рассчитанные варианты улучшения и доступные
предложения AI с рисками и условиями пересмотра. Например, при стоимости портфеля 100000 RUB,
позиции на 60000 RUB и пределе её доли 25% чистое пополнение на 140000 RUB снижает долю до 25%.
Вариант предполагает наличие дополнительных средств. Для сокращения позиции учитываются
подтверждённые расходы. При неизвестных расходах показывается условный эффект до расходов
и условия, которые требуется уточнить для допустимости варианта.

AI объясняет подготовленные варианты и материалы RAG. Числа подставляются из рассчитанных
показателей, ссылки проверяются по сохранённым версиям. При недоступной модели или ошибочном
ответе остаются рассчитанные ограничения и варианты. Короткий горизонт и неполные данные
учитываются при проверке допустимости.

Кнопка «Основания предложения» открывает исходный профиль, показатели, риски и материалы.
`/advice` показывает сохранённые предложения выбранного счёта после полной доставки отчёта.
Кнопка «Записать гипотезу» запускает привычный ввод buy/sell/hold, тикера и собственного
обоснования. Журнал сохраняет гипотезу с текущей ценой и связью с исходными доказательствами.
Повторное нажатие показывает уже записанную гипотезу. Её основания доступны также из `/journal`.
Подробности находятся в `docs/portfolio_advice.rst`.

### Подбор акций

`/stocks` предлагает фундаментальный, технический и совместный режимы. Прямые команды —
`/stocks fundamental`, `/stocks technical`, `/stocks combined`. Для MVP российский бизнес
подтверждается значением `countryOfRisk RUS` в карточке бренда брокера. Проверяются ограничения
выбранного счёта, квалификация, необходимые тесты, ликвидность и свежесть цены.

Методика `russian-business-v1` требует медианный оборот от 10 млн RUB по последним 20 дневным
свечам и цену давностью до 7 дней. Дневная свеча с одной датой считается доступной через
двое суток в UTC. В карточке приводится дата исходной свечи. Состав и версии выборки сохраняются.

Фундаментальные показатели пересчитываются по подтверждённым строкам отчётности с периодом,
валютой, стандартом и ссылкой на источник. Для финансового сектора используются P/E и P/B.
Для остальных отраслей рассчитываются также долговая нагрузка и доступная оценка EV/EBITDA.
Упрощённая EV равна капитализации плюс долг минус денежные средства. Корректировки на
неконтролирующие доли требуют дополнительных данных. Отрицательная прибыль делает P/E
неприменимым. Для отраслевого сравнения нужны минимум два других эмитента с сопоставимыми
периодами, валютой и стандартом. Отсутствующие данные показываются в карточке.

Технический блок содержит моментум за 1/3/12 календарных месяцев, SMA 50/200, RSI 14 Уайлдера,
дневную волатильность, просадку и относительный объём. Итог совместного режима — среднее
двух полных отраслевых рангов. Персональный порядок учитывает профиль и эффект одного лота
на денежный остаток, долю бумаги и сектора. Комиссия и цена исполнения требуют проверки.

`/stocks история` открывает сохранённые отчёты. Команды из отчёта позволяют посмотреть
следующих кандидатов и причины исключения конкретной бумаги. Подборка использует общую
очередь отчётов. Повтор одного запроса сохраняет первоначальные режим и результат.
Подробности методики находятся в `docs/stock_screening.rst`.

Прогнозы на 12 календарных месяцев используют локальные JSON-артефакты Ridge из
`forecast-models` или `FORECAST_MODELS`. В карточке сохраняются исходная и сценарные цены,
версия модели, временная проверка и ограничения. Модель требует завершённых датированных
обучающих примеров и подтверждённой согласованности исходной истории с корпоративными
действиями. Проверочный набор в `tests/fixtures/forecast_training.json` синтетический,
его артефакт предназначен для проверки вычислений. Для рабочих прогнозов нужен подтверждённый
рыночный набор. Методика, обучение, обновление и формат `price-bases.json` описаны в
`docs/growth_forecasts.rst`. `/stocks гипотеза ID ТИКЕР` связывает кандидата и его прогноз
с собственной гипотезой пользователя.

### Проверка обоснованности

Подготовлены 30 фиксированных сценариев на публичных котировках трёх банков и
сконструированных портфелях и профилях. Отдельный запуск с настроенной LLM сохраняет
протокол, все предложения и отказы, материалы эксперта и незаполненную рубрику.
Человек оценивает цель, горизонт, риск, доказательства и ограничения. Основная метрика —
процент обоснованных предложений среди проверенных, рабочий порог 85%.
Команды запуска, ввод вердиктов и ограничения набора описаны в
`docs/recommendation_evaluation.rst`.

### Открытые источники и поиск материалов

Стандартный реестр содержит RSS Интерфакса и публичную отчётность Сбербанка за 2025 год.
Загрузчик поддерживает RSS/Atom, HTML и текстовые PDF. В отчёте показываются исходная ссылка,
время последней успешной загрузки и состояние каждого канала.
[RSS Интерфакса](https://www.interfax.ru/rss.asp),
[отчётность Сбербанка](https://www.sberbank.com/common/img/uploaded/files/info/reporting_q4_aolql6na_2025.pdf).

Для своего реестра создайте JSON-файл и задайте путь через переменную окружения
`EVIDENCE_SOURCES`. Пустой массив отключает открытые каналы. Пример файла с новостной лентой.

```json
[
  {
    "id": "interfax",
    "name": "Интерфакс",
    "url": "https://www.interfax.ru/rss.asp",
    "format": "rss",
    "refresh_seconds": 1800
  }
]
```

Для отчётности задаются `format` со значением `pdf` или `html`, `instrument_ids` с тикерами
либо UID и `reporting_period`. Доверенные сертификаты публичных сайтов можно задать через
`EVIDENCE_CA_FILES`, по умолчанию используются пути из `TINVEST_CA_FILES`.
HTTP-клиент открытых источников имеет собственное подключение.

Документы сохраняются неизменяемыми версиями. Ссылки отслеживания объединяются, исходные ссылки
каждого канала остаются в атрибуции. Новая версия доступна с первого получения её содержания.
Исторический поиск использует версии и привязки к эмитенту, подтверждённые к выбранной дате.
Дата публикации сохраняется отдельно. Исправленный текст, впервые полученный сегодня,
участвует в анализе начиная с сегодняшнего подтверждения.

Поиск RAG использует SQLite FTS5, нормализацию русских окончаний и фильтры эмитента и даты.
Финансовые показатели сохраняют валюту, единицы, стандарт, консолидацию, период и страницу.
Неоднозначные строки таблиц сопровождаются ограничениями извлечения. RSS обновляется раз в
30 минут, отчётность раз в сутки. Ограниченные повторы учитывают `Retry-After`, после ошибки
используется датированный кэш. Подробности и примеры поиска находятся в `docs/market_evidence.rst`.

Полнота оценок и истории операций видна в отчёте. Для сложных инструментов, валютных пересчётов
и корпоративных событий могут потребоваться дополнительные данные. Источник отчётности MCP
предоставляет календарь публикаций; анализ содержания возможен при наличии опубликованных
показателей или текста в ответе источника. Отсутствующие даты, ссылки и недоступные источники
обозначаются явно. Для первого отчёта события запрашиваются за последние 7 суток.

Типы, идентификаторы и текущие цены, отсутствующие в ответе портфеля MCP, запрашиваются отдельно.
Для облигаций цена в процентах номинала переводится в деньги с учётом доступного НКД.
Строка «Контекст для AI» показывает количество подготовленных событий и позиций, включая позиции
без оценки. Доступность денежных оценок указана отдельно. При большом портфеле контекст ограничивается
по объёму, поэтому AI может получить только часть позиций; численные разделы рассчитываются по всему снимку.

Для объяснения AI задайте `LLM_BASE_URL`, `LLM_MODEL` и, если провайдер требует авторизацию,
`LLM_API_KEY`. `LLM_BASE_URL` содержит базовый адрес API, например `https://inference.dahl.global/v1`.
Время ожидания чтения ответа настраивается через `LLM_TIMEOUT_SECONDS`, по умолчанию 180 секунд.
Численные разделы рассчитывает приложение. При отсутствии LLM, ошибке провайдера
или некорректных ссылках AI на данные бот отправляет доступные рассчитанные разделы и события
с отметкой о недоступности объяснения.

### Расписание

Откройте `/schedule`, выберите «Интервал» или «Календарь», затем часовой пояс. Доступны кнопки
«Москва» и «UTC» и ввод любого IANA-имени, например `Asia/Yekaterinburg`.

- Для интервала введите `6ч` или `3д`. Первый отчёт будет назначен через этот интервал.
  Для своего первого запуска после интервала допишите дату и местное время в формате
  `ДД.ММ.ГГГГ ЧЧ:ММ`. Интервал в днях означает последовательность отрезков по 24 часа.
- Для календаря введите `ежедневно 09:00`, `будни 19:00` или `пн,ср,пт 12:00`.
  Календарное правило сохраняет местное время в выбранном часовом поясе.
- Проверьте счёт, правило, часовой пояс и следующий запуск, затем нажмите «Сохранить».

В предпросмотре кнопка «Период анализа» позволяет задать любое положительное число
завершённых календарных дней. Например, еженедельный отчёт может показывать динамику за 30 дней.
Для нового расписания предлагается 30 дней. Слово `сравнение` сохраняет политику сравнения
с последним доставленным аналитическим отчётом. Существующие расписания сохраняют прежнюю
политику при обновлении приложения. Изменение частоты доставки сохраняет выбранный период.

Кнопка «Разделы» выбирает анализ, анализ с советами, анализ с подбором акций или все разделы.
Подбор акций в расписании использует совместный режим. Личные советы учитывают подтверждённый
профиль. Настройки сохраняются после окончательного предпросмотра. Ручной `/analysis`
и `/stocks` работают независимо от периода и состава расписания.

Через `/schedule` можно изменить правило, поставить доставку на паузу и возобновить её.
Отмена незавершённой настройки сохраняет действующее расписание. При смене счёта через
`/account N` расписание переключается на новый счёт с показом ближайшего запуска. История
сравнения остаётся отдельной для каждого счёта.

Отключение токена приостанавливает автоматическую доставку и отменяет ожидающие выполнения.
После подключения токена откройте `/schedule`, выберите «Возобновить», проверьте предпросмотр
и сохраните правило. В `/schedule` также видны состояние последнего отчёта и назначенный повтор.
Время календарного правила, попавшее в разрыв при переводе часов, переносится на первый допустимый
момент после разрыва. Повторяющееся местное время выполняется один раз в первое вхождение.

### Запуск, обновление и восстановление

Фоновый обработчик запускается вместе с `investment-assistant`. Для автоматической доставки процесс
бота должен работать. Расписания, очередь, снимки и готовые части отчётов хранятся в той же SQLite-базе.
После простоя пропущенные сроки объединяются в один актуальный отчёт, затем продолжается исходный ритм.

При временной ошибке выполняется до трёх попыток. Сроки повторов сохраняются в базе, а ограничения
частоты Telegram учитываются по `retry_after`. Подтверждённо отправленные части сохраняют номера
сообщений, а повтор продолжает доставку оставшихся частей готового отчёта.

Статус «исход доставки неизвестен» означает, что соединение прервалось без подтверждения Telegram.
Этот отчёт сохраняет прежнюю точку сравнения. Будущие плановые запуски продолжаются, а новый ручной
отчёт доступен через `/analysis`. Статус последнего выполнения и причина паузы видны в `/schedule`.

Перед обновлением остановите процесс бота и сделайте копию файла из `JOURNAL_DB` (по умолчанию
`journal.sqlite3`). Например, из корня проекта в PowerShell при стандартном имени базы.

~~~powershell
$portfolioBackup = 'journal.' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sqlite3'
Copy-Item -LiteralPath '.\journal.sqlite3' -Destination $portfolioBackup
python -m pip install -e .
investment-assistant
~~~

При запуске приложение транзакционно добавляет аналитические таблицы и индексы. Повторный запуск
миграции безопасен для существующих записей журнала и подключений. При откате остановите бот и
верните предыдущую версию приложения. Дополнительные таблицы могут храниться для последующего
обновления. Восстановление файла из резервной копии возвращает данные на момент её создания.

Версия схемы SQLite 2 добавляет хранение исторических состояний и их исходных данных, версий профиля,
документов и финансовых фактов, предложений, прогнозов и экспертных оценок. Исторический анализ,
профили, персональные предложения и подборки используют датированные записи с исходными версиями.
Доступные команды и условия получения прогнозов описаны выше.

Записанную версию аналитических данных можно повторно прочитать и использовать для воспроизведения
расчёта. Изменение содержания требует новой версии. Профили и частные результаты ограничены владельцем
и счётом, публичные материалы сохраняют исходную ссылку и дату доступности. Значения с недостаточной
полнотой хранятся как неизвестные, точные денежные величины — десятичными строками.

После обновления схемы откат приложения выполняйте вместе с восстановлением предыдущей базы при
остановленном процессе. Сохраните возможность использовать прежний ключ шифрования при восстановлении.
Подробное описание данных и проверки процедуры находится в `docs/analysis_storage.rst`.

## Метрики кода

~~~powershell
python -m pip install -e ".[metrics]"
.\scripts\metrics.ps1 -Out metrics\after
~~~

Скрипт запускает готовые инструменты и сохраняет их вывод в `metrics\after`:

* **radon** — индекс сопровождаемости, цикломатическая сложность, LOC/SLOC/LLOC, метрики Холстеда;
* **lizard** — CCN, NLOC и число параметров функций;
* **flake8 + mccabe** — правило C901 (порог в `.flake8`);
* **pylint** — глубина наследования и проверки дизайна (пороги в `pyproject.toml`);
* **pyscn** — CBO, LCOM4, связанность модулей, когнитивная сложность, дублирование (`pyscn.html`);
* **coverage.py** — покрытие тестами.
