Хранение аналитических данных
========================================

Версия схемы
----------------------------------------

``JournalRepository`` добавляет таблицы схемы 2 при открытии базы версии 1.
Миграция выполняется транзакционно. Ошибка откатывает новые столбцы, таблицы,
поисковый индекс и номер версии. Повторное открытие применённой схемы сохраняет
существующие записи журнала, подключения, расписания, отчёты и подтверждения
доставки.

Прежние отчёты получают вид ``analysis``. Прежние расписания получают политику
``legacy_delivered`` и сохраняют установленное время запуска. Период и версия профиля
фиксируются при создании нового запроса. Готовый отчёт сохраняет манифест входов,
периода, доказательств, выборки и версий моделей. Возобновление доставки использует
те же сохранённые части и исходные значения.

Состав записей
----------------------------------------

* ``AnalysisPeriod`` хранит местные даты, часовую зону и зафиксированные
  UTC-границы полуоткрытого периода.
* ``HistoricalState`` хранит состояние счёта на историческую дату,
  денежные остатки по валютам и связь с опорой и исходными операциями.
* ``DataCoverage`` обозначает полноту состава, денег, операций, корпоративных
  действий и цен состояниями ``complete``, ``partial`` и ``unavailable``.
* ``InvestorProfile`` содержит ревизию подтверждённых потребностей пользователя.
* ``EvidenceDocument`` и ``EvidenceChunk`` связывают версии публикаций
  с фрагментами поискового индекса SQLite FTS5.
* ``FinancialFact`` связывает показатель, единицы и период с версией документа
  и подтверждающим фрагментом.
* ``AdviceProposal`` содержит владельца, счёт, ревизию профиля и основания.
* ``GrowthForecast`` хранит исходную цену, даты, модель и сценарные значения.

Денежные значения сохраняются через ``Decimal`` и десятичные строки.
Неизвестное значение хранится как ``null``, ноль сохраняет самостоятельный
смысл. Времена требуют часовой пояс и восстанавливаются в UTC. Новые модели
используют ``schema_version=1`` независимо от номера схемы SQLite.

Версии и изоляция
----------------------------------------

Повторная запись совпадающей версии идемпотентна. Попытка заменить её содержимое
вызывает ошибку. Новое содержание документа или профиля получает новую версию.
Запись профиля проверяет последовательность ревизий в транзакции.

Историческое состояние и его исходные данные записываются одной транзакцией.
Манифест исходных версий должен совпадать с переданными данными. Чтение частных
состояний, входов, предложений и прогнозов фильтруется по владельцу и счёту.
Финансовый факт ссылается на существующий фрагмент нужной версии документа.
Дата его доступности учитывается при историческом чтении.

Резервная копия и восстановление
----------------------------------------

Перед обновлением остановите бот и скопируйте файл из ``JOURNAL_DB``.
Сохраните прежний ключ шифрования в защищённом локальном хранилище для
расшифровки ранее подключённых токенов. Пример для стандартной базы в PowerShell
из корня проекта приведён ниже.

.. code-block:: powershell

   Copy-Item -LiteralPath '.\journal.sqlite3' -Destination '.\journal.before-schema2.sqlite3'
   python -m pip install -e .
   python -m investment_journal

После проверки остановите бот перед восстановлением. При откате приложения
верните согласованную предыдущую версию базы.

.. code-block:: powershell

   Copy-Item -LiteralPath '.\journal.before-schema2.sqlite3' -Destination '.\journal.sqlite3' -Force

Проверки ``tests/test_analysis_migration.py`` работают с временной копией
базы версии 1, проверяют её исходное содержание, результат миграции,
повторное открытие и откат ошибки. ``tests/test_analysis_storage.py``
проверяют неизменяемость версий, сохранение после открытия и изоляцию данных.

.. code-block:: console

   python -m unittest discover -s tests -p test_analysis_migration.py -v
   python -m unittest discover -s tests -p test_analysis_storage.py -v

Исторический период
-------------------

Команда ``/analysis период`` запрашивает часовой пояс IANA и две местные даты.
Прямой запрос ``/analysis 01.10.2026 31.10.2026 Europe/Moscow`` охватывает
все дни октября. ``/analysis 30 Europe/Moscow`` выбирает 30 завершённых
календарных дней. ``/cancel`` завершает диалог. Без аргументов команда
использует прежнее сравнение с доставленным снимком.

UTC-границы фиксируются до получения данных. Состав восстанавливается
от текущего подтверждённого наблюдения, включая закрытые позиции.
Дата поручения может предшествовать исполнению, поэтому запрос операций
начинается с Unix-эпохи и проходит страницы до подтверждённого конца.
Ошибка или предел пагинации отражаются в покрытии.

Цена берётся из завершённой часовой свечи до границы. Методика
``history-valuation-v1`` допускает возраст до 14 суток и показывает время
свечи. Валютные пары подтверждаются номиналом и валютой каталога брокера.
Для облигаций необходимы номинал и НКД на московскую дату оценки.
Для фьючерса учитывается переоценка от последней расчётной цены,
уже отражённой в деньгах. Полная стоимость контракта хранится отдельно
как экспозиция. Отсутствующие исторические параметры сохраняются как
неизвестные значения. При корпоративном изменении количества нужна
подтверждённая база корректировки цены.

Неизвестные оценки исключают полный итог, сохраняя стоимость известной
части. Неполные денежные движения исключают итог после внешних потоков.
Доказательства включают опору, операции, корпоративные события, параметры
оценок, цены и курсы. ``replay_history`` воспроизводит их без сети.

.. automodule:: investment_journal.historical_service
   :members: replay_history

Проверки ``test_portfolio_dispatcher.py`` проходят обычный диалог с
подменёнными внешними сервисами. ``test_historical_analysis.py`` проверяет
пополнение, закрытую позицию, повтор после полуночи и воспроизведение.

Профиль потребностей
--------------------

``/profile`` запрашивает цель, положительное целое число месяцев, категорию
риска, допустимую просадку, денежный минимум с трёхбуквенной валютой,
пределы доли позиции и сектора. Проценты больше нуля и до 100 включительно.
После предпросмотра пользователь подтверждает сохранение. ``/cancel``
оставляет прежнюю версию. Подтверждения хранятся неизменяемыми ревизиями.

Выполнение фиксирует ревизию при создании. Перед отправкой каждой части
проверяется её актуальность. Изменение профиля отменяет устаревший отчёт,
сохраняя его исходную версию и подтверждённые части доставки.

Методика ``profile-v1`` сравнивает абсолютные оценки позиций с положительной
стоимостью портфеля, считает валютные и подтверждённые отраслевые экспозиции.
Суммы передаются в одной валюте оценки. Неизвестный сектор сохраняется
неизвестным. Нехватка ликвидности рассчитывается только при совпадении
валют денежного остатка и профиля. Горизонт меньше 12 месяцев отмечается
как несовместимый с 12-месячным прогнозом. Просадка сохраняется как
заявленный пользователем предел. Неполные оценки сопровождаются покрытием.

Обычный анализ доступен без заполнения профиля. В отчёте появляется
подсказка ``/profile``. Проверки ``test_profile_metrics.py`` покрывают
ограничения, короткий горизонт, валюты и неполноту. Диалог и отмена
проверяются через Dispatcher в ``test_portfolio_dispatcher.py``.
